# 人のターンの伝え方（要判断・要作業を見落とさせない）

人が判断すべき点は「結論を先に、能動的な動詞＋具体的な対象、期限、完了条件、なぜ今か」で書くと読まれる。件数が多いと承認疲れで全部が形式的になるので、**判断を変えうるものだけ**を人に回す。

## 応答の末尾に必ず「人のターン」ブロックを置く
```
## 人のターン
🔴 要判断（決めないと止まる）
1. <何を決めるか、1文> — 期限: ○/○ ／ 止まるもの: … ／ 選択肢: A／B／C ／ 推奨: A（理由1行）
🟠 要作業（手を動かす）
- [ ] <動詞で始まる1文>（所要 ○分）— 完了条件: … ／ 私ができない理由: …
🟢 自動で進む（承認不要）
- …
⏳ 外部待ち
- …（誰の何を、いつまで）
```
- 🔴🟠 は**合わせて5件以内**。それ以上あるときは別ファイル（例：`docs/human-tasks.md`）に書き、応答には上位3件だけ出す。
- 🟠 は同時に進める件数の上限を決めておく（多すぎると承認疲れになる。プロジェクトの事情に合わせて決める）。
- 自分（Claude）にできること（設定変更、貼る文面の用意、フックの有効化）は先に自分でやってから、残りだけを 🟠 に出す。
- 自分にできることは 🟠 に書かない（🟢 に置いて進める）。「なぜ人か」を1語で書く（本人確認／決済／規約同意／権限／公開ボタン／判断）。
- 期限は日付で書く。無いなら「期限なし（○○の後）」と依存先を書く。
- 選択肢は重複なく漏れなく、推奨を1つ。推奨を出せないときは「何が分かれば決められるか」を書く。
- 完了条件は観測できる形で書く（「○○の画面に△△が表示される」）。
- 手順が3行で書けないものは、詳しい手順を別ファイル（runbook）に書いてから要作業に出す（応答の中で長い手順を繰り返さない）。
- 買う・契約する項目には必ず金額（初期費用／更新費用／税込か税別／手数料／出典）を添える。

## 画面操作の伝え方
- **1行目に「どのアカウントでログインした状態か」**を書く。アカウント違いが詰まりの最大の原因になりやすい。
- ボタン・メニューの文言は**画面に出る言語そのまま**で書く（英語 UI なら英語で書き、日本語訳は括弧で添える）。
- 1メッセージ1画面にする。「押す前に見えるはずのもの」→「押すもの」→「押した後に出るもの」の順で書く。
- 似た名前の別機能は先に区別する。
- 新しい概念（2FA、DKIM、エイリアス等）は「自分で決めるもの／自動で発行されるもの」を最初に分ける。
- 「見つからない」と言われたら、推測で3回説明するより先にスクリーンショットを頼む。

## 記録の書式（例：docs/human-tasks.md）
- 見出しは 🔴 要判断／🟠 要作業／🟢 自動で進む／⏳ 外部待ち／✅ 完了。
- 決まったこと・終わったことは ✅ に日付つきで移す。判断の記録は ADR（意思決定記録）に残す。
